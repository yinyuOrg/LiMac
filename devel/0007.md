## 2026/07/29 Ansible playbook 去重与架构适配

## What

- `ansible/playbook.yml` 中 Docker/Chrome/VSCode 三个几乎相同的 block（每段 5 步：删 legacy .list → 下 GPG key → deb822_repository → apt update → 装包）合并为 4 个统一 loop 任务，`update_cache` 从 3 次合并为 1 次
- 仓库声明数据化到 `ansible/vars/default.yml` 的 `apt_repos` 列表，新增 repo 只需在该列表加一项
- WeChat 支持 aarch64：`wechat_deb_url` 改为按 `ansible_facts['architecture']` 从 `wechat_deb_urls` 表中查找；`aarch64` 对应已验证存在的 `WeChatLinux_arm64.deb`
- Google Chrome 仓库项新增 `arches: [amd64]` 守卫，循环任务 `when: item.arches is not defined or apt_arch in item.arches` 控制，ARM 上自动跳过
- WeChat 安装用 `block/always` 包裹 `get_url` 与 `apt`，无论成败都清理 `/tmp/wechat.deb`；增加 `rescue` 步骤记录失败原因
- WeChat block 加 `when: wechat_deb_url != ""` 守卫，未知架构时整体跳过而非失败

## 改动说明

| 区域 | 改动 |
|---|---|
| `ansible/vars/default.yml` | 新增 `wechat_deb_urls`（含 x86_64 / aarch64 两项）与 `apt_repos`（含 docker / google-chrome / vscode 三项），把硬编码从 playbook 迁移到数据驱动；google-chrome 项加 `arches: [amd64]` |
| `ansible/playbook.yml` | 删除三个重复 block；改为 4 个 `loop: "{{ apt_repos }}"` 任务（删 legacy .list / 下 GPG key / 加 deb822 仓库 / 装包）；`update_cache` 仅保留初始与加完所有 repo 后两次；"Add user to docker group" 保留为独立任务；WeChat block 用 `block/always` 包裹保证清理，新增 `rescue` 与 `when` 守卫 |
| `ansible/playbook.yml:14` | 新增 `wechat_deb_url: "{{ wechat_deb_urls[ansible_facts['architecture']] | default('') }}"` |
| `bin/install-via-ansible` | 未改 |

## 验收标准

- `ansible-playbook --syntax-check` 通过
- `ansible-playbook --list-tasks` 显示 14 个任务（含循环），不再有 "Install Docker"、"Install Google Chrome"、"Install VSCode" 三个独立 block
- playbook 文件从 168 行缩到 114 行
- 真机（Debian 13 x86_64）：Docker、Chrome、VSCode、WeChat 均能正常安装或跳过
- 真机（aarch64）：Docker、VSCode、WeChat 可安装；Chrome 自动跳过；`/tmp/wechat.deb` 不残留
- WeChat 安装中途失败时，`/tmp/wechat.deb` 仍被清理（`always` 块生效）

1. 语法检查：
   ```bash
   bash -n bin/update-flake
   ```
2. 成功路径测试（stub 掉 `nix`，不真实更新 lock）：
   ```bash
   stub=$(mktemp -d) && printf '#!/bin/sh\nexit 0\n' > "$stub/nix" && chmod +x "$stub/nix"
   touch flake.lock.backup.00000000_000001 flake.lock.backup.00000000_000002
   PATH="$stub:$PATH" bin/update-flake
   ls flake.lock.backup.*    # 旧备份被删，仅保留本次备份
   rm -f flake.lock.backup.* # 清理
   ```
3. 失败路径测试：
   ```bash
   stub=$(mktemp -d) && printf '#!/bin/sh\nexit 1\n' > "$stub/nix" && chmod +x "$stub/nix"
   PATH="$stub:$PATH" bin/update-flake   # 应退出码非零且保留备份
   ls flake.lock.backup.*
   rm -f flake.lock.backup.*
   ```

## 2026/08/19 update-flake 失败保护、备份收敛与提示修正

## What

- `bin/update-flake`：
  - `nix flake update` 失败时不再留下孤儿备份后静默退出，改为打印失败与恢复提示并以非零码退出。
  - 成功后清理旧的 `flake.lock.backup.*`，**仅保留最新一份**，避免根目录备份无限堆积。
  - 修正结尾提示：删除会报错的 `nix build`（flake 无默认包），改为 `nix flake check --no-build` 与带 `--impure` 的 home-manager switch 命令，并保留 activationPackage 构建提示。
- 删除仓库根目录遗留的未跟踪文件 `flake.lock.backup.20260818_115021`。

## Why

- 原脚本每次运行都新增一个 `flake.lock.backup.*` 且从不清理，根目录持续累积。
- `nix flake update` 失败时未提示、未清理，备份成为孤儿。
- 提示的 `nix build` 在本 flake 下无默认输出，必然报错，误导用户。

## 改动说明

| 区域 | 改动 |
|---|---|
| `bin/update-flake` 更新失败分支 | 打印失败与恢复提示，保留备份，非零退出 |
| `bin/update-flake` 成功后 | 删除旧 `flake.lock.backup.*`，仅保留最新一份 |
| `bin/update-flake` 结尾提示 | `nix build` → `nix flake check --no-build` + home-manager switch |
| 根目录 | 删除遗留 `flake.lock.backup.20260818_115021` |

## 验收标准

- `bash -n bin/update-flake` 通过
- 成功路径：旧备份被清理，仅保留最新一份，`flake.lock` 未被 stub 误改
- 失败路径：退出码非零、备份保留、给出恢复命令

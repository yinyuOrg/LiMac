## 2026/08/10 修复 WSL 优化块未生效、增加幂等补齐、移除 claude-code

## What

- 修复 `ask_wsl_optimization` 的 stdout 污染 bug：函数内的 `echo` 与 `log_info` 输出全部被调用方的 `$(...)` 捕获，导致返回值混入日志文本，`[ "$use_wsl_optimization" = true ]` 永不成立，WSL 优化块从未写入 host.nix
- 新增 `ensure_wsl_profiles`：WSL 环境下每次运行脚本都检查既有 host.nix 是否缺少 profiles 优化块，缺失时**询问用户后**备份并补齐（幂等）
- 抽取 `detect_is_wsl` / `wsl_profiles_block` 两个共用函数，消除检测逻辑与模板文本的重复
- 从 `home/profiles/ai.nix` 移除 `claude-code`，并删除 `home/packages.nix` 中为其服务的 `allowUnfreePredicate` 白名单

## Why

- bug 根因：`$(ask_wsl_optimization)` 捕获函数全部 stdout，而函数内部的提示性输出（空行 `echo`、多条 `log_info`）都写 stdout，返回值被污染
- 历史遗留：已生成的 host.nix 不会重新进入交互流程（脚本直接复用），缺少的优化块永远不会被补上，需要幂等保障
- `claude-code` 是 unfree 软件，二进制缓存不存在，每次安装都需本地构建且要从海外拉取包体，国内网络下频繁超时，按用户要求移除

## 改动说明

| 区域 | 改动 |
|---|---|
| `bin/home-manager-setup` `ask_wsl_optimization` | 函数内 `echo`/`log_info`/`log_warning` 全部重定向到 stderr，仅最后的返回值走 stdout |
| `bin/home-manager-setup` 新增 `detect_is_wsl` / `wsl_profiles_block` | WSL 检测与 profiles 块模板单一来源，供两处复用 |
| `bin/home-manager-setup` 新增 `ensure_wsl_profiles` | WSL + host.nix 存在 + 无 `embedded.enable` 时，询问后备份并用 awk 在末尾 `}` 前插入优化块 |
| `bin/home-manager-setup` `main` | `generate_host_config` 之后调用 `ensure_wsl_profiles` |
| `home/profiles/ai.nix` | 移除 `claude-code` |
| `home/packages.nix` | 移除 `allowUnfreePredicate` 白名单（仅服务于 claude-code） |

## 2026/08/19 host.nix 生成转义、弃用 API 替换、死代码清理、备份按需、$HOME 路径修正

## What

- **host.nix 生成转义**：`bin/home-manager-setup` 新增 `escape_nix_string()`（转义 `\` 与 `"`）；`generate_host_config` 对用户名、Git 用户名/邮箱转义后再写入 heredoc，特殊字符不再破坏生成的 Nix 语法。同时所有交互 `read -p` 统一为 `read -rp`（不加 `-r` 时 bash 会吞掉输入中的反斜杠）。
- **弃用 API 替换**：`home/common.nix`、`home/fish.nix`（2 处）、`home/profiles/core.nix`、`flakeModules/home-manager.nix` 中 `pkgs.stdenv.isLinux/isDarwin` 全部改为 `pkgs.stdenv.hostPlatform.isLinux/isDarwin`（共 5 处），消除评估期 deprecation 告警。
- **死代码清理**：`flakeModules/home-manager.nix` 的 `mkHomeConfig` 删除未使用的 `_name` 参数，调用处同步更新。
- **备份按需**：`enable_experimental_features` 先检查目标行是否已存在，已存在则直接跳过（不再备份）；仅在确需追加时备份。
- **$HOME 路径修正**：`configure_konsole`、`show_completion` 中硬编码的 `/home/$user`、`/Users/$user` 统一改为 `$HOME`，非标准 home 目录不再出错。

## Why

- git 用户名/邮箱含 `"` 或 `\` 时，生成的 `host.nix` 语法损坏，后续 home-manager 评估直接失败（安全层面也避免了字符串注入）。
- `stdenv.isLinux/isDarwin` 已被上游标记弃用，每次评估产生告警。
- `_name` 参数从未使用；`enable_experimental_features` 每次运行都产生无谓备份；硬编码 home 路径与 `$HOME` 不一致。

## 改动说明

| 区域 | 改动 |
|---|---|
| `bin/home-manager-setup` 新增 `escape_nix_string` | 转义 `\` 与 `"` |
| `bin/home-manager-setup` `generate_host_config` | 用户名/Git 用户名/邮箱转义后写入 host.nix |
| `bin/home-manager-setup` `enable_experimental_features` | 已配置则跳过；仅追加前备份 |
| `bin/home-manager-setup` `configure_konsole`/`show_completion` | fish 路径改用 `$HOME`，删除冗余 whoami 与平台分支 |
| `home/common.nix`、`home/fish.nix`、`home/profiles/core.nix`、`flakeModules/home-manager.nix` | `stdenv.isLinux/isDarwin` → `stdenv.hostPlatform.*`（共 5 处） |
| `flakeModules/home-manager.nix` | `mkHomeConfig` 删除 `_name` 参数 |
| `bin/home-manager-setup` 所有 `read -p` | 统一为 `read -rp`，输入中的反斜杠按字面处理（否则 `read` 会吞掉 `\`，转义无从谈起） |

## 验收标准

- `bash -n bin/home-manager-setup` 通过
- 含 `"` 与 `\` 的输入生成的 host.nix 转义正确且 `nix-instantiate --parse` 通过
- 已配置 experimental-features 时运行不产生备份；未配置时产生备份并追加
- `show_completion` 输出使用 `$HOME` 下的 fish 路径
- `nix fmt`、`nix flake check --no-build` 通过且无 deprecation 告警
- `profiles.core.enable` 纯评估仍为 `false`（回归）

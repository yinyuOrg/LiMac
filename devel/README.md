# devel/ 开发变更记录

本目录沉淀本仓库**每次改动**的详细记录：改了什么、为什么改、如何验证。目的：让未来的自己或新接手的人无需翻 git blame 与 issue 就能理解每处设计的来龙去脉（典型例子：`home/fish.nix` 中 `cat $argv |` 的写法来自 [0020] 记录的 fish-shell#5714 陷阱）。

## 编号规则

- 文件名 `NNNN.md`，四位数字递增，取**下一个可用编号**，不复用、不重排。
- 一次改动一份记录；同一批强相关的多点改动可合并为一份（如 [0019]）。

## 章节结构

```markdown
# [NNNN] 改动主题

## 如何验证
（可直接照跑的命令与预期结果）

---

## YYYY/MM/DD 改动主题

## What
（改动清单，逐条列出）

## Why
（动机、背景、权衡；踩过的坑与相关 issue/文档链接）

## 改动说明
| 区域 | 改动 |
|---|---|

## 验收标准
（判定改动合格的客观条件）

## 相关文件
```

说明：

- 纯文档类记录可用「如何预览」替代「如何验证」（见 [0001]）。
- `Why` 中若涉及对早前记录的修正或区分，显式引用编号（如 [0022] 对 [0013] 的说明），避免读者困惑。
- 验证命令尽量写成复制即用；涉及临时环境的（如 `mktemp -d` 模拟 HOME）要包含清理步骤。

## 与其他文档的分工

| 文档 | 内容 |
|---|---|
| `README.md` | 面向使用者：快速开始、平台支持、日常维护入口 |
| `docs/OPERATIONS.md` | 面向使用者：详细操作手册与疑难解答 |
| `devel/NNNN.md` | 面向维护者：单次改动的完整上下文与验证方法 |

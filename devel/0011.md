# [0011] 修复 update-flake 的 diff 功能

## 如何验证

1. 语法检查：
   ```bash
   bash -n bin/update-flake
   ```
2. 功能测试（模拟 flake.lock 变更）：
   ```bash
   rm -rf /tmp/uf && mkdir -p /tmp/uf/bin
   cp bin/update-flake /tmp/uf/bin/ && cp flake.nix /tmp/uf/
   printf '{\n  "a": 1\n}\n' > /tmp/uf/flake.lock
   sed -i 's|^nix flake update$|sed -i "s\|1\|2\|" flake.lock|' /tmp/uf/bin/update-flake
   /tmp/uf/bin/update-flake   # 应输出 unified diff
   rm -rf /tmp/uf
   ```
3. 首次运行（无 flake.lock）不应报 `BACKUP_NAME: unbound variable`。

---

## 2026/08/10 修复 update-flake 的 diff 功能

## What

- `bin/update-flake` 的变更展示由 `nvd diff` 改为 `diff -u`
- 增加 `${BACKUP_NAME:-}` 保护，首次运行（无 flake.lock）时跳过 diff

## Why

- `nvd diff` 只能比较 Nix store 闭包/derivation，无法比较 flake.lock JSON 文件，每次都会报错，被 `|| true` 掩盖，导致"Changes in flake.lock"功能从未生效
- `set -u` 下 `BACKUP_NAME` 未定义时（首次运行）脚本会报错退出

---

## 改动说明

| 区域 | 改动 |
|---|---|
| `bin/update-flake:35-40` | 删除 nvd 分支，直接使用 `diff -u "$BACKUP_NAME" flake.lock \|\| true` |
| `bin/update-flake:35` | 条件增加 `-n "${BACKUP_NAME:-}"` 保护 |

---

## 验收标准

- 有旧 flake.lock 时输出 unified diff
- 无旧 flake.lock 时正常结束，不报 unbound variable
- `bash -n` 通过

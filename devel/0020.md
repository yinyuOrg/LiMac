## 2026/08/19 decolorize：修复 macOS 静默失效，规避 fish 函数 stdin 陷阱

## What

- `home/fish.nix` 移除 abbr `decolorize = "sed -r \"s/\\x1B\\[...//g\""`，改为同名 fish 函数：
  ```
  cat $argv | string replace -ra '\x1B\[([0-9]{1,3}(;[0-9]{1,3})*)?[mGK]' ''
  ```
- 支持原有用法：`cmd | decolorize`（stdin）与 `decolorize file`（文件参数）。

## Why

- 原实现依赖 GNU sed 特性：正则 `\xHH` 十六进制转义与 `-r` 标志。macOS 自带 BSD sed 两者均不支持（`\x` 被当普通字符，模式永远匹配不到 ANSI 序列；旧版本 macOS 对 `-r` 直接报错），在 macOS 上静默失效，与项目「跨平台统一」目标相悖。
- fish 内置 `string replace -ra` 使用 RE2 正则，原生支持 `\x1B`，无外部 sed 方言差异。
- 实现过程中发现 fish 自身缺陷（fish-shell issue #5714，2019 年提出至今未关闭，fish 4.8.1 实测复现）：**函数体内的 `string` 无法读取管道传入的 stdin**（同场景下 `cat` 正常、管道直连 `string` 正常）。因此函数体采用 `cat $argv | string replace ...` 经 cat 中转，同时兼容 fish 3.x 与 4.x。

## 改动说明

| 区域 | 改动 |
|---|---|
| `home/fish.nix` `shellAbbrs` | 删除 `decolorize`（sed 版） |
| `home/fish.nix` `functions` | 新增 `decolorize` 函数：`cat $argv \| string replace -ra '...' ''` |

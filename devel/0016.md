## 2026/08/19 profile 清单单一数据源

## What

- `bin/home-manager-setup` 新增 `load_profiles()`：用 sed/grep 从 `home/packages.nix` 的 `profileMeta` 块解析出 `name:描述` 列表；文件缺失或解析为空时报错退出。
- `select_profiles()` 移除硬编码的 7 项 profile 数组，改为遍历 `load_profiles` 结果；先整体读入数组再逐项询问，避免外层 `while read` 与交互式 `read` 争抢 stdin。
- `render_profiles_block()` 移除硬编码的 `all_profiles=(core python java cpp ai embedded containers)`，改为遍历 `load_profiles` 输出的名称渲染。
- `home/packages.nix` 的 `profileMeta` 描述升级为原脚本中的详细文案（含具体工具示例），成为 profile 名称、描述、顺序的唯一数据源。

## Why

- 此前 profile 清单分散在三处：`select_profiles` 的交互数组、`render_profiles_block` 的 `all_profiles`、`packages.nix` 的 `profileMeta`。新增 profile 需同步改三处，易漏改导致交互/渲染/模块三者不一致。
- 选择 sed/grep 解析而非 `nix eval`：零依赖、无需网络与 flakes 实验特性，且在 setup 首次运行阶段避免全量评估 nixpkgs 的开销；`nix fmt`（nixfmt）+ CI 保证源文件排版稳定，解析可靠。
- 不用 `mapfile`/关联数组，保持 bash 3.2 兼容（macOS 自带 bash）。

## 行为变化

- 交互式选择顺序跟随 `profileMeta` 定义顺序（现为 ai 在前，原脚本为 core 在前）。
- 交互文案与模块 option 描述统一，去掉「启用」前缀。

## 改动说明

| 区域 | 改动 |
|---|---|
| `bin/home-manager-setup` 新增 `load_profiles` | sed/grep 解析 `profileMeta`，输出 `name:描述`；缺失/为空时报错退出 |
| `bin/home-manager-setup` `select_profiles` | 删除硬编码数组，改用 `load_profiles`；先读入数组再提示 |
| `bin/home-manager-setup` `render_profiles_block` | 删除 `all_profiles` 数组，改用 `load_profiles` 结果渲染 |
| `home/packages.nix` `profileMeta` | 描述升级为含工具示例的详细文案（唯一数据源） |

## 验收标准

- `bash -n bin/home-manager-setup` 通过
- `load_profiles` 从当前 `packages.nix` 解析出 7 条 `name:描述`
- EOF 输入下 `select_profiles` 返回空（默认全部不启用）
- `render_profiles_block "core java"` 仅 core/java 为 true，block 顺序与 profileMeta 一致
- `project_dir` 指向空目录或 `packages.nix` 缺少 `profileMeta` 时，`load_profiles` 报错且退出码为 1
- 临时 HOME 下 `generate_host_config` 生成的 `host.nix` 含正确 profiles 块与 git 配置
- `nix fmt`、`nix flake check --no-build` 通过

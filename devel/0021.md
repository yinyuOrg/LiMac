## 2026/08/19 新增非交互模式

## What

- `bin/home-manager-setup` 新增命令行参数：
  - `--profiles LIST`：非交互启用指定 profile（逗号/空格分隔；空串 = 显式全部不启用），立即经 `load_profiles` 校验，未知名称报错并列出有效值；
  - `--git-name` / `--git-email`：首次生成 host.nix 时免交互写入 Git 信息；
  - `-h/--help`：输出用法。支持 `--opt value` 与 `--opt=value` 两种写法。
- 新增函数：`usage`、`parse_args`、`validate_profiles_list`、`current_enabled_profiles`、`sorted_profiles_list`。
- 三个场景接入 CLI：
  - `generate_host_config`：git 信息与 profile 按 CLI 分流；
  - `ensure_profiles`：CLI 模式免确认直接补齐；
  - `maybe_reselect_profiles`：CLI 模式按排序后的列表比对，**一致则幂等跳过（不产生备份）**，不同则替换。
- 顺带修正 `maybe_reselect_profiles` 展示用 grep 模式 `[a-z]+` → `[a-z][a-z0-9_-]*`（原名会漏掉含连字符/数字的 profile）。
- host.nix 已存在时传 `--git-name/--git-email` 会打印警告（Git 信息仅首次生成时写入）。
- `README.md` 第二步与 `docs/OPERATIONS.md` §4 补充非交互示例。

## Why

- 批量装机/WSL 自动 provisioning 场景无法回答交互提问；此前没有任何跳过手段。
- `--git-name/--git-email` 一并纳入：否则全新机器仍会在 Git 信息处停下，做不到无人值守。
- 幂等比对让脚本可安全重复执行（CI/自动化重试不产生多余备份与写入）。

## 改动说明

| 区域 | 改动 |
|---|---|
| `bin/home-manager-setup` 全局 | 新增 `CLI_PROFILES` / `CLI_PROFILES_SET` / `CLI_GIT_NAME` / `CLI_GIT_EMAIL` |
| `bin/home-manager-setup` 新增函数 | `usage`、`parse_args`、`validate_profiles_list`、`current_enabled_profiles`、`sorted_profiles_list` |
| `bin/home-manager-setup` `main` | 先 `parse_args "$@"`；`--profiles` 时先校验再进入流程 |
| `bin/home-manager-setup` `generate_host_config` | git 信息与 profile 支持 CLI 免交互；host.nix 已存在时警告 git 参数被忽略 |
| `bin/home-manager-setup` `ensure_profiles` | CLI 模式免确认补齐 |
| `bin/home-manager-setup` `maybe_reselect_profiles` | CLI 模式比对（顺序无关）幂等跳过或替换；展示 grep 模式修正 |
| `README.md` / `docs/OPERATIONS.md` | 补充非交互模式示例与说明 |

## 验收标准

- `bash -n bin/home-manager-setup` 通过
- `--help` 退出码 0；未知参数/未知 profile/缺参数值均报错退出
- 无 stdin 输入时可用 `--profiles/--git-name/--git-email` 完成首次生成
- 缺块补齐、块比对幂等跳过、块替换三种场景均符合预期
- 不带任何参数时交互行为与改前一致（EOF 默认全不启用、重选默认 N 跳过）

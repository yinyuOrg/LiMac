## 2026/08/19 profile 默认值改为 false；rm 别名仅在 core 启用时生效

## What

- `home/packages.nix`：`profiles.<name>.enable` 选项默认值由 `true` 改为 `false`。
- `home/fish.nix`：`rm = "trash"` 别名改为 `lib.mkIf config.profiles.core.enable { ... }`，仅在 core profile 启用时生效；模块参数新增 `config`。

## Why

- [0013] 已将初始化流程改为「默认全部不启用、显式选择」，但模块选项默认值仍为 `true`：当 `~/.config/limac/host.nix` 缺少 profiles 块，或纯评估（如 `nix flake check`、fallback 用户 `limac`）时，会静默启用全部 profile，与 0013 原则矛盾。
- `trash` 命令由 `home/profiles/core.nix` 的 `trash-cli` 提供。用户一个 profile 都不选时，`rm` 别名指向不存在的命令，导致 `rm` 不可用。加条件后 core 禁用时自然回退为系统 `rm`。
- 正常运行流程不受影响：`bin/home-manager-setup` 生成的 host.nix 始终显式写出全部 profile 的 true/false；旧文件缺块由 `ensure_profiles` 引导补齐。

## 改动说明

| 区域 | 改动 |
|---|---|
| `home/packages.nix:25` | `profiles.<name>.enable` `default = true` → `default = false` |
| `home/fish.nix:1-5` | 模块参数新增 `config` |
| `home/fish.nix` `shellAliases` | `rm = "trash"` 改为 `lib.mkIf config.profiles.core.enable { rm = "trash"; }` |

## 验收标准

- `nix fmt`、`nix flake check --no-build` 通过
- 纯评估下 `profiles.core.enable` 为 `false`
- core 禁用时 `programs.fish.shellAliases` 不含 `rm`；core 启用时 `rm` 别名为 `trash`
- `bash -n bin/home-manager-setup` 通过（脚本未改动，仅确认）
